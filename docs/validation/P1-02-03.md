## Code réel

- XP configurable : passif 1, hostile 5, élite 40 ; courbe 40 + 4L + 0,25L².
- Niveau 1–100, compteurs longs saturants, points par niveau ; le niveau n'impose aucun alignement.
- Alignement entier : passif -1, hostile +1, élite +5, boss Sith +250/Jedi -250 ; cap ±1000.
- Dernier dommage significatif effectif, propriétaire serveur de la source/projectile, délai court configurable. Une mort environnementale sans attribution explicite Force ne reprend pas un ancien coup. Les FakePlayers de machines sont exclus.
- Paiement unique par UUID de mob : marqueur persistant du mob + historique joueur borné de 256 événements.
- Anti-farm : par joueur/type de mob/dimension/cellule de 32 blocs, au-delà de 20 kills sur 1200 ticks : XP ×0,25 arrondie vers le bas et 0 alignement. Fenêtre, seuil, taille et multiplicateur configurables. Historique borné et persistant.
- Classification par tags. Hostiles : tag explicite ou Enemy vanilla ; passifs : liste explicite ; élites initiales : piglin brute et ravager. Autres mobs non classés : aucune récompense. Tags exclusion/entraînement et boss prioritaires.
- Service public `core.api.PlayerProgressService` pour lecture/énergie et récompenses de boss. Cooldown par joueur/boss persistant ; aucun vrai boss encore créé.
- Bandes d'alignement de présentation et conditions indépendantes de niveau/alignement pour les futurs pouvoirs. Aucun arbre de compétences complet présenté comme fini.
- `/lotf debug add_xp <1..1000000>` : uniquement OP 2, outil de test sans modification d'alignement.

## Limites à garder ouvertes

- Test solo/serveur intégré et deux clients graphiques stables non terminés (incident GLFW documenté dans P1-01).
- Les unités couvrent la récompense de boss ; éligibilité de participation et butin dépendront des arènes P4, aucun boss réel validé.
- Historique de 256 événements : le marqueur persistant sur le mob et les futurs états d'arènes sont indispensables ; ce cache seul ne garantit pas la déduplication infinie d'événements arbitraires.
- Crash brutal entre sauvegarde joueur et sauvegarde du marqueur de mob : non validé. Les écritures concernent deux stockages Minecraft distincts ; ne pas annoncer une transaction disque atomique.
- Attribution Force indirecte (chute après projection) à ajouter avec P1-05 ; actuellement une mort environnementale est refusée même après un coup direct.
- Petits dégâts létaux sous le seuil sans attribution précédente au même joueur ne paient pas.
- Les seuils de présentation sont les défauts de la spécification ; leur surcharge configurable reste à intégrer avec l'écran profil.
